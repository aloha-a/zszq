# 项目过程记录

## 2026-11-20　项目框架与本地联调

### 推进与产出

按规格中的职责建立活动、抢购、订单和模拟 TA 四个 Java 21 模块。选择 Maven 聚合构建，四个服务分别生成可执行 JAR。用 Compose 启动 MySQL、RabbitMQ、Nginx 以及五个 Java 进程，其中两个是抢购实例。业务库和模拟 TA 库共享本地 MySQL 实例，分别建表。启动命令和端口见[开发说明](../README.md)。

### 实际问题与处理

| 现象 | 定位与尝试 | 处理效果 |
| --- | --- | --- |
| 首次构建应用镜像时中断 | 构建日志指向 Docker Hub 令牌请求超时。此前已通过 Docker 引擎成功拉取 Maven 和中间件镜像，单独执行 `docker pull eclipse-temurin:21-jre-alpine` 也成功。 | 复用本地运行镜像，按原 Compose 配置重新构建，四个模块均打包成功。 |
| 抢购服务的就绪测试在消息队列离线时返回 503 | 测试使用可连接的内存数据库及不可连接的 RabbitMQ 端口。把抢购就绪检查明确设为应用状态与数据库两项，订单服务则保留 RabbitMQ 检查。 | 抢购就绪端点返回 200，响应中的数据库组件为 `UP`。 |
| TA 容器显示健康，经网关请求却返回 400 | 逐个请求四个入口，定位到 `/health/ta`。TA 的 Tomcat 日志指出 Host 中含下划线。修正了 Nginx 上游名称，执行配置校验并重载。 | 同一项 HTTP 冒烟测试重跑通过，四个入口均返回 `UP`。 |

### 本轮验证

| 操作 | 实际结果 |
| --- | --- |
| 在构建容器中运行 `mvn -B -ntp verify` | 四个 Java 模块构建成功，抢购就绪与订单消息路由的两项 JUnit 测试通过。 |
| 执行 `docker compose up -d --build --wait` 并查看容器状态 | MySQL、RabbitMQ、网关、活动、订单、TA 和两个抢购实例共八个容器均为 `healthy`。 |
| 执行 `python -m unittest discover -s tests/smoke -v` | 两项测试通过。四个服务的就绪检查可从网关访问，连续十次请求观察到两个抢购实例的上游地址。 |
| 查询 MySQL 元数据 | `zszq` 中七张业务表、`zszq_ta` 中一张结果表。已核对活动与用户的联合唯一键、单号与流水类型的联合主键，以及待发消息的单号与事件类型唯一键。 |
| 查询 RabbitMQ 的队列与绑定 | 订单队列和死信队列均为持久化 quorum 队列。正常交换机与死信交换机上的 `purchase.accepted` 均绑定到预期队列。 |
